**SPEC-01 — Show 2 or 4 agents on the landing page**

Analyze the following and write a recommendation with rationale:

- The spec lists 4 agents: Voice Lead (LIVE), Lead Scout (LIVE), Pre-Call Brief (PROPOSED), Follow-Up Radar (PROPOSED).
- Option A — Show 2 agents only: cleaner page, no "coming soon" confusion, but undersells the vision and scope of the suite.
- Option B — Show all 4, mark PROPOSED as "coming soon": shows full product vision, creates anticipation, sets expectations for roadmap. Risk: if PROPOSED agents take too long, "coming soon" ages poorly.
- The target audience is Italian SMB owners (not technical). They buy on trust and concrete outcomes, not roadmaps.
- The product already has 2 live agents with strong before/after numbers (90 seconds vs 30 min). That is the conversion hook.
- "Coming soon" on a landing page built before the product is widely known can read as vaporware to skeptical SMB owners.

Write the recommendation: recommend showing all 4 agents with clear LIVE / COMING SOON badges. Rationale: the two live agents do the conversion work; the two proposed agents show the vision is bigger than a single tool. The badge system manages expectations explicitly. If at any point the proposed agents ship, the badges become LIVE with no structural change to the page.

**SPEC-06 — Tech Stack**

Analyze the following and write a recommendation:

- Option A — Next.js + Tailwind CSS: SSR/SSG for SEO, built-in i18n routing (IT/EN), great developer experience, large ecosystem, Framer Motion for animations, Vercel deploy.
- Option B — Plain HTML + Tailwind CSS: zero-dependency, ultra-fast, no build step. But: manual i18n (no routing), no component system, Framer Motion requires React, harder to maintain if sections grow.
- The landing has 8 sections, 2 languages, animations (hero entrance, scroll reveals, hover states), a contact form, and SEO requirements (meta tags, Open Graph, schema markup).
- Phase 3 requires structured schema markup and optimized meta tags — easier to manage in Next.js with `<Head>` and metadata API.
- The user manages deploy — Vercel is one-click from Next.js.
- There is no backend needed (form can use a third-party service like Formspree or Resend).

Write the recommendation: recommend Next.js (App Router) + Tailwind CSS. Rationale: i18n routing, SEO metadata API, Framer Motion compatibility, and Vercel deploy are significant advantages for this project's requirements. The complexity cost is low for a single landing page.

Format:
```
## SPEC-06: Tech Stack

**Decision:** Next.js 15 (App Router) + Tailwind CSS v4

**Rationale:** [3-5 sentences — i18n, SEO, Framer Motion, deploy]

**Key choices within stack:**
- Routing: App Router with `/[lang]` segment for IT/EN
- Styling: Tailwind CSS v4 (utility-first, no custom CSS except design system tokens)

- Deploy: Vercel (one-command deploy from GitHub)
- Language: TypeScript

**Impact on Phase 2:** TECH-01 — scaffold Next.js 15 project with App Router, Tailwind v4, Framer Motion installed.

**Status:** APPROVED
```
