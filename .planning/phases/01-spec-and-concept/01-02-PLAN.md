Invoke the `brainstorming` skill per SKILL-CATALOG instructions (REQUIREMENTS.md Phase 1, skill #1).

This is a hard gate — do not invoke ui-ux-pro-max until this step produces an approved direction.

Brainstorm the design direction for a B2B landing page targeting Italian SMB owners in field-sales-intensive industries (construction, manufacturing, distribution). The product replaces friction (CRM/spreadsheet) with WhatsApp voice notes. The value proposition is speed, simplicity, and trust.

Explore and validate:

1. **Visual tone**: Should it feel like enterprise SaaS (cool, blue, geometric) or like a trusted local partner (warm, grounded, clear)? What signals trust to an Italian SMB owner who has been burned by tech products before?

2. **Color direction**: Consider:
   - Deep navy/slate + warm amber/orange accent: professional + energetic, works for B2B without feeling cold
   - Forest green + cream: trustworthy, grounded, not tech-bro
   - Near-black + electric blue: modern, clean, but might feel too "startup"
   - Which palette reads as "Italian craftsmanship meets modern efficiency" to a 45-year-old construction company owner?

3. **Typography**: Humanist sans-serif (friendly, approachable) vs geometric sans-serif (precise, modern) vs a serif accent for authority? Consider readability on mobile (many users will view on iPhone while in the field).

4. **Density**: Italian SMB owners are not designers. Dense = overwhelming, too sparse = unserious. What density feels right for a landing page that must convert in one scroll?

5. **Animation register**: Subtle and purposeful (scroll reveals, badge pulse on LIVE) vs no animation (faster, safer) vs hero entrance sequence? What feels credible, not gimmicky, to the target?

Output from brainstorming: a clear direction statement (2-3 sentences) per topic above. This becomes the brief for ui-ux-pro-max.

After the brainstorming produces a validated direction, immediately proceed to Task 2 within the same execution. Do not pause for user confirmation unless a genuine conflict or ambiguity is found.

<task type="auto">
  <name>Task 2: Generate design system with ui-ux-pro-max</name>
  <files>design-system/MASTER.md</files>
  <action>
Invoke `ui-ux-pro-max --design-system --persist` using the direction from Task 1.

Create `design-system/MASTER.md` with the full design system. This file is the single source of truth for all Phase 2 visual decisions.

The design system MUST include:

**1. Design Principles** (3-4 sentences — what this design system optimizes for)

**2. Color Palette**
- Primary color + shades (50–950 scale)
- Secondary/accent color + shades
- Neutral scale (gray/slate)
- Semantic tokens: `color-background`, `color-surface`, `color-text-primary`, `color-text-secondary`, `color-border`, `color-live-badge`, `color-coming-soon-badge`
- Provide hex values for each

**3. Typography**
- Font family: heading font + body font (Google Fonts or system fonts only — no paid fonts)
- Scale: xs, sm, base, lg, xl, 2xl, 3xl, 4xl, 5xl (with px values)
- Weight usage: when to use 400, 500, 600, 700
- Line-height rules for hero headlines vs body text
- Mobile scaling: which sizes reduce at 375px

**4. Spacing & Layout**
- Base unit (4px or 8px)
- Section padding: mobile vs desktop
- Container max-width and padding
- Grid: column count at 375px, 768px, 1024px, 1440px

**5. Component Rules** (for each component used in the landing)
- Hero section: background treatment, headline size, CTA button style
- Agent card: dimensions, badge placement, before/after stat display, hover state
- LIVE badge: color, shape, optional pulse animation spec
- COMING SOON badge: color, shape (muted)
- Section dividers: how sections are separated
- CTA button (primary): size, color, radius, hover state
- CTA button (secondary/ghost): style
- Form inputs: border, focus ring, error state
- Pricing table row: column layout, number display

**6. Animation Guidelines**
- Hero entrance: what animates, duration, easing
- Scroll reveal: trigger point, duration, which elements
- Card hover: what transforms (scale? shadow? border?)
- LIVE badge pulse: whether to include, duration
- Principle: animation should feel earned, not decorative

**7. Iconography & Visual Assets**
- Icon style: line icons (not filled), size guidelines
- No stock photos — abstract shapes or minimal illustrations if needed
- Agent avatars: recommended approach (geometric, initials, or abstract symbol per agent)

**8. Dark/Light Mode**
- Decision: light mode only for v1 (Italian SMB owners are not dark-mode-first users)
- Semantic tokens defined above make future dark mode possible

**9. Tailwind Config Tokens**
- Provide the Tailwind config extensions (colors, fontFamily, fontSize, spacing) as a code block
- This is what the Phase 2 executor pastes into `tailwind.config.ts`

Write all values explicitly — no "choose a shade of blue." Every field must have a specific, usable value.
