  <action>
    Invoke skill: `impeccable audit` — full UX and accessibility review of the complete landing page.

    **Audit checklist to run against every section:**

    1. CONTRAST — Verify 4.5:1 for normal text, 3:1 for large text (18px bold or 24px regular):
       - white on navy-900 (#0F2349): ~13:1 — PASS
       - slate-700 (#334155) on slate-50 (#F8FAFC): ~9.8:1 — PASS
       - amber-500 (#F59E0B) on navy-900: ~3.5:1 — WARNING for body text (use amber as accent only, not body)
       - navy-300 (#93C5FD) on navy-900: check ratio — if below 4.5:1 for subheadline, switch to white
       - slate-400 (#94A3B8) on white: 3.3:1 — FAIL for body text — ensure slate-400 is only used for labels/placeholders, never body copy
       - Fix any contrast failures before proceeding.

    2. ALT TEXT — Every icon and SVG:
       - Decorative Lucide icons: `aria-hidden="true"` on the SVG
       - Informative icons: `aria-label="[description]"` on the wrapper element
       - No stock photos in v1 (per MASTER.md §7) — skip image alt text

    3. FOCUS STATES — Every interactive element must have visible amber focus ring:
       - Buttons: `focus-visible:outline-3 focus-visible:outline-amber-400 focus-visible:outline-offset-2`
       - Links (navbar, language switcher, calendar link): same amber focus ring via Tailwind
       - Form inputs: amber border + `box-shadow: 0 0 0 3px rgba(245,158,11,0.15)` on focus (MASTER.md §5 spec already)
       - Verify: Tab through entire page — no element "disappears" when focused

    4. KEYBOARD NAVIGATION — Logical tab order:
       - Navbar: logo → IT link → EN link → CTA button
       - Main: through form fields → submit → calendar link
       - Agent cards: add `tabIndex={0}` and `role="article"` if they have no inner interactive element

    5. FORM ACCESSIBILITY:
       - Every `<input>` and `<textarea>` has a `<label htmlFor="field-id">` with matching `id`
       - Required fields: `required` attribute
       - Error message region: `role="alert"` so screen readers announce immediately on error
       - Success message region: `role="status"` and `aria-live="polite"`
       - Submit button: `disabled={status === 'submitting'}` prop — prevents double-submit

    6. SEMANTIC HTML fixes to apply:
       - Each section: `<section aria-labelledby="section-id-h2">` with matching `id` on H2
       - Navbar: `<nav aria-label="Main navigation">`
       - Language switcher: `aria-current="page"` on the active locale link
       - Pricing: convert CSS Grid divs to semantic `<table>`, `<thead>`, `<tbody>`, `<th>`, `<td>`
       - Footer: `<footer>` element wrapping footer content
       - H heading hierarchy: H1 = Hero only, H2 = all section headings, no skipping levels

    7. REDUCED MOTION: Confirm `globals.css` prefers-reduced-motion override is present (from 02-01).

    **Apply these specific fixes:**
    - `ContactForm.tsx`: `aria-live="polite"` on success div, `role="alert"` on error div, `disabled={status==='submitting'}` on submit button
    - `LanguageSwitcher.tsx`: `aria-current="page"` on active locale `<Link>`
    - `Navbar.tsx`: wrap nav links in `<nav aria-label="Main navigation">`
    - `Pricing.tsx`: rebuild pricing table as semantic `<table>` with `<th scope="col">` headers
    - All section components: add `id="section-name-heading"` to H2, `aria-labelledby="section-name-heading"` to `<section>`
    - `Badge.tsx`: add `aria-hidden="true"` to the decorative pulse dot span
